# Интеграция браузера SHELTER с сервером (P2)

Документ описывает **замороженные** контракты, которые использует клиент
(`Everick-Ven/shelter`). Форматы ответов менять нельзя: сервер гарантирует их
соблюдение, а тесты — фиксируют.

Базовый адрес сервера задаётся в клиенте одной переменной окружения сборки
(например, `SHELTER_API_BASE_URL`); все пути ниже — относительные.

---

## 1. Общие правила

- Все запросы — **HTTPS**. По http сервер в production отвечает `301` на https.
- Аутентификация — **cookie-сессия** `shelter_session`
  (`HttpOnly`, `Secure`, `SameSite=Lax`). Токен в БД не хранится, только SHA-256.
- Клиент обязан отправлять cookie: `credentials: 'include'` / `CURLOPT_COOKIEFILE`.
- Все ошибки имеют единый формат:

```json
{ "error": { "code": "session_invalid", "message": "Authentication required" } }
```

Клиенту достаточно смотреть на HTTP-статус и `error.code`.

- **Никакое локальное состояние клиента не является доказательством подписки.**
  Единственный источник правды — ответ `premium.status` от сервера.
  При недоступности сервера, таймауте или ошибке клиент обязан считать
  подписку **неподтверждённой** (fail-closed) и не включать платные функции.

---

## 2. `premium.status`

Проверка права на премиум. Вызывать при старте браузера и периодически
(например, раз в 6 часов), а также перед включением премиум-функций.

```
GET /api/v1/me/subscription
Cookie: shelter_session=...
```

Ответ `200` (формат заморожен):

```json
{
  "active": true,
  "planId": "yearly",
  "expiresAt": "2027-10-23T11:13:07.677Z",
  "status": "active",
  "reason": "paid",
  "checkedAt": "2026-10-23T11:13:07.686Z",
  "plan": { "id": "yearly", "title": "Год", "days": 365, "amountMinor": 239000, "currency": "RUB" },
  "renewable": true,
  "secondsRemaining": 31535999
}
```

Обязательные поля контракта: `active`, `planId`, `expiresAt`, `status`,
`reason`, `checkedAt`. Остальные — дополнительные, клиент может их игнорировать.

Клиент использует **только `active`**. Остальное — для диагностики и UI.

| `status` | `reason` | Что делать клиенту |
| --- | --- | --- |
| `active` | `paid` | доступ подтверждён оплатой — включить премиум |
| `active` | `granted` | доступ выдан администратором — включить премиум |
| `none` | `no_subscription` | подписки нет — предложить оформление |
| `expired` | `expired` | срок истёк — предложить продление |
| `cancelled` | `cancelled` | отменена — доступ выключен |
| `refunded` | `refunded` | возврат — доступ выключен |
| `revoked` | `revoked` | отозвана администратором — доступ выключен |
| `none` | `invalid_data` | данные повреждены — доступ **не** выдавать |
| `none` | `verification_failed` | сбой проверки на сервере — доступ **не** выдавать |

Статусы без авторизации:

- `401 session_invalid` — cookie отсутствует/недействительна. Клиент показывает
  «войдите», премиум выключен. Перезаходить в цикл запросов не нужно.

## 3. `premium.checkout`

Создание заказа и получение ссылки на оплату.

```
POST /api/v1/checkout
Cookie: shelter_session=...
Content-Type: application/json

{ "planId": "monthly", "idempotencyKey": "optional-client-key" }
```

- `planId` — **обязательно**, только `monthly` или `yearly`;
- сумма, валюта и срок берутся из серверного каталога: клиент их не передаёт
  (переданные `amountMinor`/`days`/`currency` игнорируются);
- `idempotencyKey` (8–128 символов) — необязательно: повторный запрос с тем же
  ключом вернёт тот же заказ вместо создания нового.

Ответ `201` (или `200`, если заказ уже существовал по ключу идемпотентности):

```json
{
  "orderId": "ord_r7bxezbVoanDB5p03xLJug",
  "planId": "yearly",
  "amountMinor": 239000,
  "currency": "RUB",
  "days": 365,
  "provider": "yookassa",
  "checkoutUrl": "https://yoomoney.ru/checkout/...",
  "status": "pending",
  "expiresAt": "2026-10-23T11:43:07.645Z"
}
```

Действия клиента:

1. открыть `checkoutUrl` во внешней системной браузера/вкладке
   (`ShellExecute`/`open`), **не** внутри защищённого контекста;
2. после возврата пользователя опросить `GET /api/v1/checkout/:orderId`
   или повторно вызвать `premium.status`;
3. **не включать премиум по факту возврата** — только по ответу сервера.

Каталог тарифов для витрины клиента (без авторизации):

```
GET /api/v1/plans
```

```json
{
  "currency": "RUB",
  "plans": [
    { "id": "monthly", "title": "Месяц", "amountMinor": 29900, "amount": "299 ₽",
      "currency": "RUB", "days": 30, "badge": null, "compareAtMinor": null,
      "compareAt": null, "features": ["..."] },
    { "id": "yearly", "title": "Год", "amountMinor": 239000, "amount": "2 390 ₽",
      "currency": "RUB", "days": 365, "badge": "Выгода 33%", "compareAtMinor": 358800,
      "compareAt": "3 588 ₽", "features": ["..."] }
  ]
}
```

Ошибки: `400 invalid_plan` (неизвестный тариф), `400 invalid_body`,
`401 session_invalid`, `409 order_already_paid`, `409 idempotency_conflict`,
`429 rate_limited` (20 запросов / 10 минут), `502/503` — сбой платёжного
провайдера (заказ не создан, премиум не выдаётся).

## 4. `app.checkUpdates`

Проверка наличия новой версии (канал обновлений на GitHub Releases).

```
GET /api/v1/updates/check?currentVersion=1.2.0&channel=auto
```

- `currentVersion` — **обязательно**, формат `X.Y.Z` или `vX.Y.Z`
  (только числовые версии; `1.0`, `1.0.0-beta`, `latest` отклоняются);
- `channel` — необязательно: `stable`, `beta` или `auto` (канал возьмётся из
  настроек сервера). Авторизация не требуется.

Ответ `200` (формат заморожен):

```json
{
  "updateAvailable": true,
  "channel": "stable",
  "currentVersion": "1.1.0",
  "latestVersion": "1.2.0",
  "release": {
    "version": "1.2.0",
    "tagName": "v1.2.0",
    "name": "SHELTER 1.2.0",
    "htmlUrl": "https://github.com/Everick-Ven/shelter/releases/tag/v1.2.0",
    "publishedAt": "2026-01-10T10:00:00.000Z",
    "notes": "Исправления и ускорение запуска.",
    "assets": [
      { "name": "shelter-1.2.0-setup.exe", "url": "https://github.com/.../setup.exe", "size": 1048576 }
    ]
  },
  "forceUpdate": false,
  "minSupportedVersion": "1.0.0",
  "autoInstall": false,
  "checkedAt": "2026-10-23T11:13:07.686Z"
}
```

Поведение клиента:

- `autoInstall` **всегда `false`** — автоустановка запрещена. Клиент показывает
  уведомление и открывает `release.htmlUrl` (страницу релиза) по клику;
- скачивание — только явное действие пользователя (по `release.assets[].url`
  или со страницы релиза);
- `forceUpdate: true` означает, что текущая версия ниже `minSupportedVersion`:
  рекомендуется блокирующий баннер со ссылкой на релиз (но всё равно без
  автоустановки);
- при `updateAvailable: false` ничего не показываем;
- при недоступности сервера клиент **не** предлагает обновление (никаких
  «последних известных» версий из кэша как повода к установке);
- если версия клиента нераспознана, сервер ответит
  `currentVersion: null, updateAvailable: false`.

Ошибки: `400 missing_version`, `400 invalid_query`, `429 rate_limited`
(60 запросов / 10 минут).

## 5. Вход в аккаунт из клиента

Клиенту не нужен собственный OAuth-флоу: достаточно открыть в системном браузере

```
https://<домен>/api/v1/auth/google/start?redirect=/account
https://<домен>/api/v1/auth/yandex/start?redirect=/account
```

пользователь войдёт на сайте, а клиент получит статус через `premium.status`
(если использует общее хранилище cookie браузера) либо через показ страницы
`/account` во встроенном окне.

Для сценария «встроенное окно»: открыть `https://<домен>/account` — там есть
вход, покупка подписки, история заказов, отзыв сессий и удаление аккаунта.

## 6. Удаление данных

```
DELETE /api/v1/me
Cookie: shelter_session=...
```

Ответ `200`: `{ "ok": true, "deleted": true, "revokedSessions": 2 }`.

Сервер анонимизирует профиль (email/имя/аватар → `null`), удаляет связи с
OAuth-провайдерами, отзывает **все** сессии и закрывает доступ к премиуму.
После этого текущая cookie недействительна — клиент обязан выйти из аккаунта и
выключить премиум немедленно, не дожидаясь следующей проверки.

Обезличенная бухгалтерия заказов сохраняется (для отчётности), персональных
данных в ней не остаётся.

---

## 7. Чек-лист для клиента

- [ ] `premium.status` вызывается при старте и периодически;
- [ ] премиум включается **только** при `active === true`;
- [ ] при любой ошибке/таймауте/`401` премиум выключен (fail-closed);
- [ ] локальные флаги «я премиум» не хранятся и не используются как источник правды;
- [ ] `premium.checkout` открывает `checkoutUrl` вовне, статус проверяется сервером;
- [ ] `app.checkUpdates` передаёт `currentVersion` в формате `X.Y.Z`;
- [ ] обновление — только уведомление + ссылка, без скачивания и установки в фоне;
- [ ] после `DELETE /api/v1/me` клиент разлогинивается и выключает премиум.
