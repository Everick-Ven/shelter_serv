# SHELTER · однофайловая демонстрация сервера-моста

Откройте `../shelter-demo.html` двойным кликом. Все ресурсы встроены. Нет сервера,
установки, сетевых запросов или экрана авторизации. Это демонстрация, а не готовый backend.
Переключатель ролей не является настоящей границей безопасности.

## Разделение клиента и сервера

- **Браузер**: задачи, доски, локальные имена контактов, ключи, шифрование,
  расшифровка, повтор недоставленного сообщения и кнопка проверки обновлений.
- **Сервер-мост**: обезличенные ID, согласие на связь, состояние подключения,
  передача получателю без хранения тела и без офлайн-очереди.
- **Биллинг**: тарифы, заказы, события оплаты и вычисляемый доступ.
- **Каталог релизов**: только серверные метаданные в административной панели;
  пользовательская панель не проверяет и не устанавливает обновления.

Сверено с приложенным UI: `wpSelfTaskId()` использует `SH-XXXX-XXXX`,
`wpSaveTaskContact()` хранит `{id,nick}` в клиентской адресной книге;
`wpPersonContactId()` привязывает клиентского исполнителя к ID.
Эти клиентские данные НЕ копируются в серверное демо. Согласие на связь и
безочередная доставка — демонстрация требуемой модели, не извлечённый из UI
готовый сетевой протокол.

## Как проверить

1. Пользователь → «Связи по ID». У клиента 1 ID `SH-K7MP-4N8R`.
2. Отправьте приглашение клиенту 2: `SH-T9WX-6D3H`.
3. Переключите клиент сверху, примите входящее приглашение.
4. Вернитесь в клиент 1 → «Проверка связи» → отправьте тестовый сигнал.
5. Отключите клиент 2 на той же странице, вернитесь в клиент 1 и повторите.
   Доставка отклоняется: тело не сохраняется и не ставится в очередь.
6. Разорвите связь: дальнейшая доставка запрещена.
7. Пользователь → «Подписка» → создайте заказ. Доступ не активируется.
8. Администратор → «Платежи и доступ» → «Демо-webhook» для этого заказа.
   Подписка активируется; повтор того же события не продлевает срок.
9. Симулируйте ошибку проверки: доступ не подтверждается (fail-closed).

## Данные и ограничения

Все состояние — только в оперативной памяти страницы и сбрасывается при reload.
Старый ключ localStorage прежней демоверсии удаляется при открытии; новое
состояние не записывается в localStorage, IndexedDB или файлы. Нет экспорта задач.

Тестовый пакет — синтетический блок 256 байт, очищаемый в одном вызове. Нет
пользовательского содержимого, шифрования, Yjs/CRDT или реального межустройственного
обмена. Два клиента — независимые ID в одном симуляторе, не две сетевые сессии.
Квитанция содержит только from/to/bytes/at/status. Служебный журнал в памяти
ограничен 60 событиями и не содержит тел. ID — псевдонимы: факт связи между ними
виден мосту. Не заявляется полная анонимность.

Тарифы: 299 ₽ / 30 дней и 2390 ₽ / 365 дней. Доступ вычисляется из оплаченных
заказов; первый платёж и количество оплат не дублируются в подписке. Возврат
пересчитывает доступ по остальным оплатам. Реальный backend должен проверять
аутентификацию владельца ID, подпись webhook и сумму платежа; симулятор не
доказывает наличие оплаты и не меняет рабочие API сервера.

Релизы вымышлены, версии только X.Y.Z / vX.Y.Z. Реальные bridge-контракты
`premium.status`, `premium.checkout`, `app.checkUpdates` не изменяются.

## Автотест

Только для разработки (сам HTML не требует Node.js):

```sh
npm install --prefix /tmp/shelter-demo-test jsdom
NODE_PATH=/tmp/shelter-demo-test/node_modules node demo-tests/standalone.cjs
```

Проверяет формат ID, запрет связи с собой и дубликатов, согласие получателя,
доставку без тела/очереди, офлайн-отказ, разрыв связи, роли, pending → paid,
идемпотентность webhook, частичный возврат, fail-closed, версии каталога,
все страницы, отсутствие сетевых ресурсов и записи состояния на диск.

Дополнительно проверено в Chromium через Playwright: `file://`, приглашение,
согласие, доставка/офлайн-отказ, оплата/повтор webhook, сброс при reload,
адаптация к ширине 390px и отсутствие ошибок JavaScript и сетевых запросов.
